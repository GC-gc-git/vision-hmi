3补坑 A：Day4 的错误码断了（你的 W1 产物链有个洞）

任务：建 w1-final-日志与异常体系 工程

  1. 在 VS 里新建 Windows 窗体应用程序（net48），命名 w1-final-日志与异常体系，放在 VisionHMI\W1\ 下
  2. 从 w1-day5-日志库选型+NLog 实战 复制这 4 个文件过去：AppLogger.cs、ErrorCodes.cs、BizException.cs、NLog.config
  3. 用 NuGet 包管理器装 NLog 5.4.0（不要手改 csproj，Day5 你踩过这个坑）
  4. 把 Program.cs 改成下面这个版本（多了配置自愈和版本标记）
// Program.cs · 最终版
using NLog;
using NLog.Common;
using System;
using System.IO;
using System.Text;
using System.Threading;
using System.Windows.Forms;
using System.Xml;

namespace w1_final_日志与异常体系
{
    internal static class Program
    {
        // 默认配置模板：配置缺失或损坏时用它重建一份
        private const string DefaultNLogConfig = @"<?xml version=""1.0"" encoding=""utf-8""?>
<nlog xmlns=""http://www.nlog-project.org/schemas/NLog.xsd""
      xmlns:xsi=""http://www.w3.org/2001/XMLSchema-instance"" autoReload=""true"">
  <targets>
    <target name=""asyncFile"" xsi:type=""AsyncWrapper""
            queueLimit=""10000"" overflowAction=""Block""
            batchSize=""200"" timeToSleepBetweenBatches=""0"">
      <target xsi:type=""File""
              fileName=""${basedir}/logs/${shortdate}.log""
              layout=""${longdate}|${level:uppercase=true}|${message}""
              keepFileOpen=""false""
              archiveAboveSize=""10485760"" maxArchiveFiles=""7"" />
    </target>
  </targets>
  <rules>
    <logger name=""*"" minlevel=""Debug"" writeTo=""asyncFile"" />
  </rules>
</nlog>";

        [STAThread]
        static void Main()
        {
            Application.EnableVisualStyles();
            Application.SetCompatibleTextRenderingDefault(false);

            // ① 内部日志：NLog 自己出问题时，错误原因要能留下证据
            //    必须用编程接口，不能靠 XML（实测：XML 写 internalLogFile 无效）
            InternalLogger.LogLevel = LogLevel.Warn;
            InternalLogger.LogToConsole = true;
            InternalLogger.LogFile = Path.Combine(
                AppDomain.CurrentDomain.BaseDirectory, "logs", "nlog-internal.log");
            InternalLogger.IncludeTimestamp = true;
            LogManager.ThrowExceptions = false;

            // ② 配置兜底：缺失或损坏就自己写一份默认的
            EnsureNLogConfig();

            // ③ UI 线程未捕获异常
            Application.ThreadException += (delegate(object sender, ThreadExceptionEventArgs e)
            {
                try
                {
                    AppLogger.LogError(ErrorCodes.Unknown, "未捕获异常", e.Exception);
                }
                catch { }
                finally
                {
                    // 致命错误：立刻落盘，不能只留在内存队列里
                    LogManager.Flush();
                }

                try
                {
                    MessageBox.Show("程序遇到未处理的错误，已记录日志，请联系技术人员。",
                        "出错了", MessageBoxButtons.OK, MessageBoxIcon.Error);
                }
                catch (Exception ex2)
                {
                    System.Diagnostics.Debug.Write(ex2);
                }
            });

            // ④ 非 UI 线程未捕获异常（进程即将终止）
            AppDomain.CurrentDomain.UnhandledException += delegate(object sender, UnhandledExceptionEventArgs e)
            {
                try
                {
                    Exception ex = e.ExceptionObject as Exception;
                    AppLogger.LogError(ErrorCodes.Unknown, "进程级未捕获异常", ex);
                    // 关键：进程马上要死了，这是队列里日志的最后机会
                    LogManager.Flush();
                }
                catch { }
            };

            // ⑤ 启动信息：先知道程序起来了、配置好了
            AppLogger.LogInfo("程序启动，配置自愈检查通过");

            Application.Run(new Form1());

            // ⑥ 正常退出路径：窗体关闭后 Application.Run 才返回
            AppLogger.LogInfo("程序正常退出");
            LogManager.Flush();
            LogManager.Shutdown();
        }

        /// <summary>确保 NLog.config 存在且是合法 XML。缺失或损坏就生成默认配置。</summary>
        private static void EnsureNLogConfig()
        {
            string path = Path.Combine(AppDomain.CurrentDomain.BaseDirectory, "NLog.config");
            if (IsConfigUsable(path)) return;

            try
            {
                File.WriteAllText(path, DefaultNLogConfig, new UTF8Encoding(false));
                System.Diagnostics.Debug.WriteLine("[自愈] NLog.config 缺失或损坏，已重建默认配置");
            }
            catch (Exception ex)
            {
                // 连默认配置都写不了（权限问题），只能放弃，不能抛
                System.Diagnostics.Debug.WriteLine("[自愈失败] " + ex.Message);
            }
        }

        /// <summary>配置是否可用：文件在、XML 合法、根节点是 nlog</summary>
        private static bool IsConfigUsable(string path)
        {
            if (!File.Exists(path)) return false;
            try
            {
                XmlDocument doc = new XmlDocument();
                doc.Load(path);
                return doc.DocumentElement != null
                    && doc.DocumentElement.Name == "nlog";
            }
            catch
            {
                return false;
            }
        }
    }
}
⚠️ 顺序不能反
InternalLogger.LogToConsole = true 和 EnsureNLogConfig() 必须在 Application.ThreadException 挂载之前、在第一次写日志之前。
因为 LogManager.GetCurrentClassLogger() 一旦被调用，NLog 就会去读配置。配置坏了的话，那一刻的错误会被静默吞掉 —— 你必须先把「能看见错误」的开关打开。

4补坑 B：NLog 配置出问题时，它是静默的

我实测到的三种「静默」

场景程序表现日志表现最危险的地方
NLog.config 被删除 不报错，退出码 0 一条都写不出来，日志目录都不生成 你以为在记日志，其实什么都没记。现场出事时你才发现没证据
NLog.config XML 语法写错 不报错，退出码 0 一条都写不出来 改配置时手滑打错一个字，日志就哑了，而且没有任何提示
配置文件合法但根节点写错 不报错，退出码 0 同上 同上
✔ 一个好消息：运行中配置坏掉，NLog 不会崩
我实测过：程序跑着，我把它正在用的 NLog.config 删掉 / 改成非法 XML，已写入的 500 条日志一条不少，程序照常跑完。
NLog 的策略是「新配置加载失败就继续用旧配置」。所以配置错误不会导致日志丢失，只会导致你改的新配置没生效。这个区别很重要 —— 别把锅全甩给「NLog 不可靠」。

两个能救命的诊断开关

✘ 先纠正一个我自己写错的地方：throwExceptions 不是 NLog 的 XML 属性
我在 NLog 5.4.0 的官方 XML 文档里查过：throwExceptions 0 次命中。 它是 LogManager.ThrowExceptions 这个编程接口（静态属性），写在 <nlog> 里会被静默忽略。
我实测过：XML 里写 throwExceptions="true" + internalLogFile="..."，日志照常写出，没有任何警告，内部日志文件一个都没生成。写错的属性名不会有任何提示 —— 这正是 NLog 最坑的地方。

① LogManager.ThrowConfigExceptions = true —— 让配置错误变成异常

默认 NLog 会把配置加载错误吞掉。用编程接口打开开关，错误会直接抛出来（必须写在 LogManager 第一次加载配置之前）：

// 开发/调试期：让问题现形（写在 Program.cs 最开头）
LogManager.ThrowConfigExceptions = true;

// 实测结果（net48 + NLog 5.4.0）：
// 配置语法错误 →
//   NLog.NLogConfigurationException:
//   Exception when loading configuration ...\NLog.config
//   ---> System.Xml.XmlException: 根元素未闭合: targets, nlog
⚠️ 千万别在生产环境开着
官方文档原话（Troubleshooting logging 节）：
「throwExceptions 会让日志异常传播到调用方……只应该在排查问题时和单元测试时开启，不要在生产环境开启，否则日志出问题会导致程序崩溃。」
区分清楚：LogManager.ThrowExceptions 管运行时日志异常，LogManager.ThrowConfigExceptions 管配置加载异常。官方说后者在生产环境反而是推荐的。

② InternalLogger.LogFile —— 把 NLog 自己的错误写下来

// 让 NLog 把自己的内部错误（含配置加载失败原因）写到文件
// 注意：属性名是 LogFile / LogLevel，不是 InternalLogFile
InternalLogger.LogLevel  = LogLevel.Warn;
InternalLogger.LogFile   = Path.Combine(baseDir, "logs", "nlog-internal.log");
InternalLogger.IncludeTimestamp = true;

官方文档原话：「Internal logging 往往是排查配置加载、日志路由、target 写入问题时最有用的诊断工具。」

✔ 实测：编程接口能留下完整证据，XML 属性做不到
同样一个「配置语法错误」场景，两种写法实测对比：
做法内部日志文件内容
XML 里写 internalLogFile没生成—
代码里设 InternalLogger.LogFile17 行完整堆栈 + XmlException 的行列号
原因：配置文件语法错误时，NLog 连配置都还没加载成功，XML 里写的 internalLogFile 根本没人读。只有编程接口能在这个时间点生效。
→ 所以 内部日志必须用代码设，不能靠 XML。这是本节最值钱的一条。
我实测的一个坑
我用 InternalLogger.LogWriter = (level, msg, ex) => {...} 想接内部日志，编译报错：
CS1660: 无法将 lambda 表达式转换为类型"TextWriter"，原因是它不是委托类型
原因：InternalLogger.LogWriter 的类型是 TextWriter，不是委托。要接得自己写一个 TextWriter 子类。

但这条我后来发现不是最好的方案 —— 直接用 InternalLogger.LogFile 更省事。这条记下来就行，别真去写 TextWriter。

技术要点：
· 设计五级日志（Debug/Info/Warn/Error/Fatal）与业务错误码体系，使现场故障可按编号定位
· 实现 UI 线程与非 UI 线程的全局异常兜底，确保崩溃时堆栈完整落盘
· 通过并发写入实测（5000 条零丢失）与压力场景测试（20000 条日志），定位并修复异步队列溢出丢弃、进程退出日志丢失等可靠性缺陷
· 配置缺失/损坏时自动重建配置文件，避免日志静默失效
· 使用 Git 管理多版本工程演进

结论实测方式与数据
配置缺失 → 日志静默全丢删 NLog.config 运行 → logs 目录不生成、0 条落盘、退出码 0、配置未被重建
配置语法错误 → 同样静默写非法 XML → 同上；LogManager.ThrowConfigExceptions = true 时抛 NLogConfigurationException（含 XmlException 行列号）
运行中配置坏掉 → 不会丢日志程序运行中删掉/破坏配置，已写的 500 条一条不少，程序正常跑完
配置自愈方案有效4 种场景全过：语法错误 / 完全缺失 / 配置正常不覆盖 / 根节点写成 <wrong>
热重载可用net48，autoReload="true"，事件触发 1 次，级别集合变 Error,Fatal，改后写的 Info 被正确过滤；连跑 3 次一致
并发不丢行10 线程 × 500 条 = 5000，落盘 5000，丢失 0
关闭无残留进程net48 WinForm，后台线程 + 窗体关闭 → tasklist 查不到进程，退出码 0，日志 102 行完整
崩溃路径要手动 Flush崩溃处理器里加一次 Flush()：20000 条从 11094 救回到 20006（全部落盘）
throwExceptions 不是 XML 属性NLog 5.4.0 官方 XML 文档中 throwExceptions 0 次命中；它在 XML 里被静默忽略（日志照常写出，无任何警告）
内部日志必须用编程接口同一「配置语法错误」场景：XML 写 internalLogFile → 0 个文件；代码设 InternalLogger.LogFile → 17 行完整堆栈
